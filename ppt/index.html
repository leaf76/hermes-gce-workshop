05 / 24 · Compare
Hermes vs OpenClaw
POSITIONING

Hermes vs OpenClaw

H Hermes Agent
Memory becomes reusable agent capability

不是 Hermes 才有記憶；差異是它把 memory、skills、cron、fresh sessions 接進同一個 agent loop。

  • 長期記憶不是只存 `MEMORY.md`，還會變成可重用的 skills 與 workflow。
  • GCE demo 主線是 cloud VM 上的 agent brain：模型、工具、cron、gateway 都在 server 跑。
  • 比較直的路徑：先跑通 CLI / model / memory，再接 Telegram 或 Discord。
O OpenClaw
Also has memory and can run on server

OpenClaw 也有長期記憶，也能 self-host；它的強項更偏 gateway、dashboard、nodes 與 channel orchestration。

  • Memory source of truth 通常是 workspace Markdown、daily notes、`MEMORY.md`。
  • Server 可行；但 cloud 上要另外規劃 dashboard access、auth、nodes、device/media workflows。
  • 要同等功能：需逐項補 gateway policy、channel bindings、control UI、nodes、smoke tests。

這頁要先修正一個常見誤解：不能說 Hermes 有記憶、OpenClaw 沒有。OpenClaw 也有 memory，而且用 Markdown 做 source of truth 很透明。Hermes 的差異是 memory 會更緊密地接到 skills、自我改善、cron 與 agent loop，變成長期可重用的工作能力。

第二個誤解是 cloud server。OpenClaw 也可以跑在 server；只是它的強項是 single Gateway、dashboard、multi-channel routing、nodes、device/media workflows。這場 GCE demo 的主線是 cloud VM 上長期跑 agent brain，所以 Hermes 的 installation、model、memory、cron、gateway path 比較短。

如果要讓 Hermes 達到 OpenClaw 同等功能，不是只 migrate memory 就好。要逐項補 gateway policy、dashboard/control UI 替代方案、nodes 或 device workflow、media handling、channel bindings、auth/token 設定，最後每個入口都重新 smoke test。

  • 現場注意 OAuth code 不要投影給觀眾。
02 Gemini API key
Fallback API

Hermes native `gemini` provider，使用 Google AI Studio / Gemini API。

  • 環境變數：`GOOGLE_API_KEY` 或 `GEMINI_API_KEY`。

建議把 Codex 當主線，因為現場可以善用可用免費額度；Gemini API key 留作備援，避免 Codex quota、OAuth 或區域因素卡住整場 demo。

22 / 24 · Migration
OpenClaw → Hermes
MIGRATION REALITY

先 dry-run，不要整包搬

YES Portable
Memory / Skills

Hermes 提供 `hermes claw migrate`，可預覽並匯入相容資料。

  • `SOUL.md`、`MEMORY.md`、`USER.md`。
  • 部分 provider config、allowlist、skills。
  • 用 `--dry-run` 先看會改什麼。
NO Runtime State
Sessions / Runs

OpenClaw gateway runtime 不等於 Hermes memory。

  • cron jobs 需要重新審核與重建。
  • channel bindings、sessions、runs store 不要直接當記憶搬。
  • secrets 需要明確同意，不能默默匯入。

講清楚 `hermes claw migrate --dry-run` 是第一步。不要在講台上執行真實 migration，除非事前已經備份且沒有 production impact。

官方 migration docs 也把 cron、plugins、hooks、complex channels 等列為 archive/manual review 類別。
